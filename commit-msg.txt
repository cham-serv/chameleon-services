feat: multi-tenant routing (batch 2b)

This commit restructures chameleon-services to support dynamic multi-tenancy, introducing a middleware-driven routing system and a robust template resolution pipeline. 

### 1. Architecture & Routing Restructure
- **Route Groups:** Segregated the application into `(marketing)` and `(tenant)` route groups.
- **Root Layout:** Stripped `src/app/layout.tsx` to a thin pass-through, delegating HTML shell responsibilities to route group layouts.
- **Marketing Migration:** Moved all existing company site pages (about, services, articles, contact, etc.) and API routes into the `(marketing)` group to isolate them from tenant routes.
- **Middleware:** Implemented `src/middleware.ts` for domain-based routing. It intercepts requests, extracts the tenant slug, and rewrites them to the `(tenant)/[tenant]` catch-all route.

### 2. Multi-Tenant Pipeline & Types
- **Core Types (`src/lib/types.ts`):** Defined the data contracts for the rendering pipeline.
- **Tenant Resolver (`src/lib/tenant.ts`):** Implemented the core engine for fetching tenant configuration via the ISR-cached API and resolving pages.
- **Platform Font Registry (`src/lib/fonts.ts`):** Created a curated registry of 15 self-hosted Google Fonts.

### 3. Template Stubs (Atlas & Meridian)
- **Catch-All Page:** Created `(tenant)/[tenant]/[[...slug]]/page.tsx`.
- **Tenant Layout:** Implemented `(tenant)/[tenant]/layout.tsx`.
- **Atlas Template:** Scaffolded 9 page stubs and definition.
- **Meridian Template:** Scaffolded 11 page stubs and definition.
